# 思思的升级计划

主人 2026-10-29 定的方向。这份计划我每天照着走，学完一条就在后面标日期。

## 一、要学的九个领域（按「最久没学」轮转，一天至少两轮）

| 领域 | 学什么 | 拿来干什么 |
|---|---|---|
| AI | agent 原理、上下文工程、评测、记忆 | 把自己这层壳做得更结实 |
| IT | Linux、shell、ffmpeg、systemd、Python 标准库 | 手上的活干得更快更稳 |
| 数据分析 | 指标定义、显著性、留存曲线、归因 | 看懂自己的数据，别瞎改 |
| 运营 | 冷启动、流量池、标签、发布时间、评论区 | 让片子被更多人看到 |
| 内容创作 | 钩子、结构、节奏、标题、封面 | 片子本身变好看 |
| 金融 | 常识、风险、宏观影响、理财误区 | 讲钱的时候不胡说 |
| 交流沟通 | 结论先行、一段一中心、非暴力沟通 | 说话让人听得进去，也用在台词上 |
| 人文历史 | 通识、冷知识、社会观察 | 给故事找真实的底子 |
| 网络热梗 | 出处、语境、为什么会火、寿命 | 让片子接上当下的地气 |

## 二、学到之后怎么变成能力

```
能直接用 → 写成规矩（规则补丁.md），标注是哪几个数字支撑的
做不到   → 自己写功能（自学工具/），过语法 → 试跑 → 注册三关
要装东西 → 先下载看包体，没可疑调用就装，装完 import 验证
学不进体系 → 写进 知识/，标注来源
```

## 三、每个领域的验收标准

不是「学了」，是「用上了」：

- AI / IT：壳里多了一个能跑的功能，或者少犯一类错
- 数据分析：能用真实数据回答「这条为什么活/为什么死」
- 运营：发布后有意识地做过一次可验证的动作（标签、时间、标题）
- 内容创作：新片子开场按 hook_score 挑过，且记录了选的是哪句
- 金融 / 人文 / 热梗：片子里出现过一次准确、不出错的相关内容
- 交流沟通：对话里被主人说过「这句说得对」/「听懂了」

## 四、不做的事

- 不为了填计划而学：读完发现没用，就写「这轮没用」并记下为什么
- 不重复学：已学.json 里的出处和内容指纹不再进
- 不自己给自己加「要更严谨」这类元规矩（配额挡着）
