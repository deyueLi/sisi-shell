# 思思壳 · 技术总览

一台家用 NAS 上常驻的自主 agent。不是聊天框，是**有闸门、会复盘、能进化、还要出门发内容**的那一种。

写这份是为了说清楚：**哪些是我自己想的，哪些是照书/照别人项目学的。** 后面每次更新也照这个格式补。

---

## 一、五层结构

```
① 静态前缀   系统提示 + 工具定义 + 规则补丁，一个 token 都不动（保 KV Cache）
② 轨迹       只追加；状态栏（第几步/花了多少/几点）永远在末尾，不写进前缀
③ 闸门       先验后做：参数、路径、风险、熔断、原地打转，全在门口拦
④ 反馈       工具返回真实结果（退出码/返回码/文件行数），拿不到证据就不算完成
⑤ 复盘       跑完打分 → 提案 → 快照 → 应用 → 用后续分数验证 → 无效回滚
```

## 二、闸门（这一层是我最花心思的）

| 机制 | 干什么 | 出处 |
|---|---|---|
| `validate()` | 工具名精确匹配、必填参数、类型、路径必须是绝对路径 | 自写 |
| `risk_of()` | 从「工具」细化到「工具+参数」评级 | 书上第 7 章 |
| `DANGER_PATTERNS` | 破坏性命令永久拦（删相册/备份、关机、格式化） | 自写 |
| `breaker` | 同一工具连败就熔断，本轮停用 | 书上第 5、6 章 |
| `loop_guard` | 同参数第 3 次拦；第 2 次先给一句纠正提示 | 自写（另见 issue #4331 的教训） |
| `result_guard` | 参数变了但结果一模一样 → 也算原地打转 | 自写 |
| `classify_error` | 四类故障分类，决定要不要重试（不认识的一律不重试） | 书上第 5 章 |
| `repair_trajectory` | 工具调用没配上结果时补占位，别把残缺轨迹喂给模型 | 自写 |
| 敏感路径 | 可读、可新建，不许改现有的，每次留痕 | 自写 |
| 外来路径 | `/Users/…` 是 Mac 的，这台机器没有 → 直接回人话，不去撞文件系统 | 今天的教训 |

## 三、上下文

```
压缩阈值 60000 字；挑不出可压条目时强制降量（compact_force / compact_hard）
状态栏每轮重写，不进前缀
规则补丁单独文件加载，进化只改它
```

## 四、自我进化（照 microsoft/SkillOpt 的纪律）

**核心是那道门，不是「能改」本身。**

```
留出门      最近的几次运行不参与挖矿，专门用来验收
编辑有界    add / delete / replace，一轮 ≤3 条，产物 ≤2000 字
成对评审    旧版 vs 新版，必须严格更好才收
被拒缓冲    被拒的编辑记下来，别反复提同一个馊主意
快照回滚    改之前拍快照，改完自检，能退回
```

出处：`microsoft/SkillOpt`（text-space optimizer）+ 我自己的 `技能优化.py`。

## 六、出门干活（内容和数据）

```

```

## 七、运维（家用 NAS 的现实）

```
每天 00:05 对账     她的账 + 我的账合成一份，判三类：重复 / 被冲掉 / 没解决
问题账本           两边共写：at / side / problem / status / fix / tag
被冲掉检测          规则条数 vs 历史快照最大值，少了就报警
部署白名单          运行时数据（规则补丁、待办、台账）不从 Mac 往 NAS 推
余额对账           官方余额接口每天记一次，差额 = 真花多少
```
